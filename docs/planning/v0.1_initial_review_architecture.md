# InSight Architecture Planning: Version 0.1 (Baseline / Legacy)
## Monolithic Review-Level Classification & Keyword Clustering

---

### 1. Architectural Philosophy (v0.1)
The v0.1 system was designed around standard whole-review natural language processing:
- **Input Unit**: The entire unsegmented review string (100–300 words).
- **Sentiment Model**: Calibrated Logistic Regression with Platt Scaling over high-dimensional TF-IDF unigram/bigram features.
- **Clustering Engine**: `SentenceTransformer('all-MiniLM-L6-v2')` generating 384-dimensional dense embeddings for the complete review text.
- **Topic Representation**: Class-based c-TF-IDF keyword extraction across all reviews grouped into a cluster.
- **Complaint Identification**: Inferred indirectly by measuring which clusters had a high proportion of reviews with `sentiment == "NEGATIVE"`.

```
[Full Review Text]
       │
       ▼
[PII Masking] ──► [Calibrated Logistic Regression (Whole Review)]
       │
       ▼
[MiniLM Embedding of Full Review]
       │
       ▼
[MiniBatchKMeans (Whole Reviews)]
       │
       ▼
[Filter Clusters with High Negative Ratio] ──► "Complaint Themes"
```

---

### 2. Implementation Details
- **Data Stores**: In-memory dictionary state with Neon PostgreSQL vector indexing fallback.
- **Benchmark Evaluation**: 1,000 labeled test reviews per domain evaluated for accuracy, macro-F1, and Brier score.
- **Drift Monitoring**: Population Stability Index (PSI) tracking shift in sentiment proportions across batches.
- **Verbatims**: First 3 raw reviews returned per cluster without phrase-level targeting.

---

### 3. Limitations & Failure Modes Observed in v0.1
1. **Mixed-Polarity Dilution**: Reviews with mixed sentiment (*"Love the packaging and smell, but the pump broke on day 3"*) produced ambiguous vectors. Positive tokens diluted negative tokens, causing the sentiment classifier to predict `NEUTRAL` and placing the vector between categories.
2. **Indirect Complaint Detection**: The system could only identify themes that happened to have a high overall negative percentage. Discrete complaints embedded inside 4-star or 5-star reviews were completely missed.
3. **Conversational Noise in Vector Space**: Whole-review embeddings were dragged by non-defect chatter (shipping dates, greetings, purchase context), reducing cluster separation.
4. **Verbatim Traceability Gap**: When a user inspected a theme, they had to read entire multi-paragraph reviews to find where the actual complaint was located.

---

### 4. Transition to v0.2
These observed limitations prompted the architectural pivot in **v0.2**:
- Deconstructing reviews into atomic propositions (sentences).
- Introducing a supervised sequence classification stage specifically to isolate `COMPLAINT` and `RECOMMENDATION` statements.
- Clustering *only* the extracted defect propositions with unit-normalized cosine embeddings to guarantee synonymous grouping.
